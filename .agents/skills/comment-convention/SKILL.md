# 注释规范

## 核心规则

1. **每个函数/方法都必须有注释**——导出的、私有的、Handler、工具函数，无一例外。
2. 注释用**中文**，写在函数声明正上方。
3. 注释回答的是**为什么和契约**，不是复读代码。

## 一条好注释包含什么（按需要取舍）

- **一句话用途**：这个函数存在是为了什么（必需）
- **契约**：参数语义、返回值约定、什么情况下报错（非常规时必需）
- **副作用**：改状态、发网络请求、改 DOM、启动 goroutine（有副作用时必需）
- **坑和设计权衡**：为什么这样做而不是显而易见的那种做法（有故事时必需）

## 反例（禁止）

```go

// 遍历所有 session              ← 复述代码，代码自己会说
for s := range h.sessions {
```

## 内联注释

- 只解释**不显然的**逻辑：位运算、正则、魔法数字、时序假设。
- 显然的赋值、循环、return 不写。

## 审查检查单

写完后或被审查时逐条过：

- [ ] 每个函数/方法上方都有注释？
- [ ] 有没有注释在复读代码（删掉或改写成"为什么"）？
- [ ] 副作用（网络、状态、DOM、协程）写清了吗？
- [ ] 新增公开 API 的参数边界/错误条件写清了吗？
- [ ] 改了行为后，旧注释同步更新了吗？

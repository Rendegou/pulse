# PULSE 注释规范

## 基本规则

1. 每个函数/方法都必须有中文注释：导出的、私有的、Handler、工具函数都包括。
2. 写在声明正上方；事件、定时器、goroutine 的匿名回调可以由紧邻注册点的注释说明其行为。
3. 至少说明为什么需要这个函数；非常规输入、错误条件、副作用、锁和资源归属必须写清。
4. 注释与代码一起修改，已完成的 TODO 删除；不用文件头代替函数注释。

## 契约写到什么程度

- 纯函数：输入单位、返回语义、空/越界边界、是否修改输入。
- 状态方法：改变哪些状态，调用者是否要持锁，返回值是否共享可变对象。
- 连接方法：读写方向、失败怎样退出、谁关闭 conn/channel。
- 定时或动画回调：谁创建，频率/时间单位，谁停止；绘制坐标来自哪里。
- 无特殊边界的小函数一行足够，不复述显然的循环、赋值和 return。

## 格式示例

```go
// Snapshot 为 welcome 提供此刻的公开在线信息。
// 在读锁内复制字段，返回值可在锁外序列化，不携带可变运行状态。
```

```js
// samplePosition 在接收方时间线上选取远程位置，平滑离散的网络更新。
// renderT 与样本 t 使用同一页面的毫秒时钟；无样本回退，超过最新点不外推。
```

以上是注释示例，修改对应实现后重新核对事实。不要写“设置 x”“遍历 sessions”这类只有代码表面含义的注释。

## 审查

- 每个函数/方法及业务回调都有对应说明？
- 注释是否回答用途、特殊边界和副作用？
- 时钟、坐标单位、锁和清理 owner 是否明确？
- 行为变化后旧注释与 TODO 是否同步？

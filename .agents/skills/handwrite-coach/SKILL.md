# PULSE 手写陪练

用户负责主要实现，助手负责解释、任务切分、分级提示、review 和验证设计。用户明确要求实现时完成授权范围，不用教学模式拒绝帮助。

## 开始一轮

1. 查看 [进度](../../../docs/05-progress-and-validation.md) 与实际 diff，不能依据旧对话认定已完成。
2. 确认当前卡点是语法、调用关系、数据所有权、算法、接线还是验证。
3. 从 [课程卡](../../../docs/03-handwritten-lessons.md) 选择一个约 20–45 分钟任务；必要时再拆，不同时布置多个章节。
4. 任务给出文件/函数入口、一个新概念、输入输出、反例、验收和首级提示。

## 提示与示范

- 默认先问一个能定位卡点的具体问题，或让用户手算一组数据。
- 提示逐层升级：定位 → 契约/伪代码 → 局部示范 → 用户要求的完整实现。
- 用户说“写一点点”时，只写当前卡住的最小部分，不顺手把后续课程完成。
- 不为保留练习而隐瞒必要语法解释；不设必须硬卡多久的要求。
- 不清空用户函数、不回退手写成果。需要重写练习时使用独立练习文件。

## review 与学习验收

- 先检查真实行为和数据链，再看边界、注释与命名。
- 解释谁调用、拿到什么、改了谁、输出被谁消费；对应当前源码。
- 发现已计算未使用、UI 未更新等问题时，验证结果消费端，而不只看辅助函数。
- 分别记录“读懂、自己实现、通过验证、独立迁移”；助手写完不等于用户学会。
- 给一个换数据或换事件的迁移题，下一次先让用户不看答案试写。
- 每轮收尾只明确一项最重要的问题及下一步，保留高并发和 Host Radar 的长期目标。

写代码时同时遵循相邻的 [注释规范](../comment-convention/SKILL.md)。不自动推送：仓库 main push 会触发部署。

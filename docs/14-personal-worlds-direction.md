# PULSE：自己的小世界，真实的相遇

记录日期：2026-09-09。今晚只固定方向，下一次讨论后再继续开发。

## 我们想做什么

**每个人拥有自己的小世界，可以布置、表达自己，也可以邀请别人来拜访、一起停留，逐渐留下共同的记忆。**

用户以《动物森友会》描述这种感觉，并明确选择了“在网上真实地感到另一个人就在旁边”。个人空间为相遇提供场所；实时在场感是当前最重要的体验目标。这是体验上的参照，尚不意味着要实现完整生活模拟游戏。

## 已经明确的方向

- 保留宽阔、安静的粒子海面，岛屿之间留出距离；继续使用连续靠近与有层次的近景。
- 使用岛屿作为个人空间，当前不继续做房屋造型。
- 每座岛应有表达主人的空间：布局、物件、内容和留下的痕迹都可以逐步形成差异。
- 实时互动要让人感知到对方的移动、停留与回应。后续功能优先服务于一次具体的拜访。
- 文章是一种可选内容。当前“三张书页平铺在岛上”只是原型表达，用户已提出疑问，不能当作最终内容布局。

以后评估一个新功能，先问：**它是否让这里更像主人，或让两个人更容易发生联系？** 暂时没有帮助的想法先记下，不立即扩充实现。

## 下一步建议：验证一次双人拜访

建议沿用当前视觉，做一段小而完整的体验：主人布置少量物件并保存 → 朋友通过链接来到岛上 → 双方看见彼此 → 一起让一个物件发生变化 → 再次访问时变化仍在。

“一人种下植物、另一人浇水”是讨论中提出的候选动作，**还没有确定为必做玩法**。明天先判断这个动作是否有趣，也可以选更自然的互动，不必为了遵守文档而实现它。

验证分为两部分：

- **程序是否成立：** 两个真实客户端看到同一座岛与相同变化；主人编辑、访客互动的权限清楚；刷新后布置和共同变化仍然存在。具体身份与保存方案在实施前确定。
- **相处是否有感觉：** 找一位朋友实际拜访，观察是否会等待、回应、主动尝试互动，以及之后是否想再回来。功能通过不代替这部分反馈。

先不扩展无限世界、完整建造系统、社交推荐和复杂经济玩法。首次体验能否成立，仍需要验证。

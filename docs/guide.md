# PULSE 手写开发路线

骨架只有 4 个文件，先通读一遍再动手：

```
main.go            服务端：Hub + Session + WebSocket + 真实内存指标（约 180 行）
static/app.js      前端：连接 WS + 画点画（约 140 行，课程注释在文件里）
static/index.html  页面骨架
static/style.css   样式
```

规则：**你写，我陪练**。每次实现一小块，我负责讲设计意图、审查代码、补测试、指出坑。
不要一次性把课程全做完——每一课都对应文档里的一个真实概念。

---

## 课程 1：光标同步（Presence 的核心手感）

**入口**：`static/app.js` 底部的注释 + `main.go` 的 `readPump`。

- 前端：监听 `mousemove` → 归一化到 0..1 → **20Hz 采样**后发送 `{type:"cursor",x,y}`
- 服务端：解析 cursor 消息 → 更新 Session → 广播 `{type:"delta",id,x,y}`
- 前端：收到别人的 delta 就移动对应的点

**文档依据**：§11——浏览器原始鼠标事件有几百 Hz，不能全发。采样、量化、delta 编码是这课的三个关键词。

**思考题**：如果 50,000 人同时移动光标，全量广播会发生什么？（§12 AOI，先想好再写下一课）

## 课程 2：点击脉冲

点击画布 → 你的点发出一圈扩散波 → 其他人也看到。

新概念：消息类型又多了一种。想想消息格式怎么设计才不用为每种事件写一套解析。

## 课程 3：Idle / Focus

`document.visibilitychange` + 活动时间戳。空闲的点亮度下降（文档 §3.1）。
服务端要知道多久没收到 cursor 算 idle——但**不要为每个连接起一个 timer**（§13：timing wheel 是后面的课）。

## 课程 4：Host Radar（假的，但接口要是真的）

写一个 goroutine 定期编造 `host_event`（来源、端口、SYN/ESTABLISHED）广播出去。
前端在画面边缘画出"有东西在敲端口"的线条。

**关键**：消息格式按将来真实 sensor 会输出的格式设计。这样课程 6 换真数据时前端一行不用改。

## 课程 5：真实指标面板

底部四个指标已经是真的了（读一读 `main.go` 里怎么拿到的）。
加上：在线时长、join/leave 速率、每秒消息数。

## 课程 6：真 Host Sensor（需要 Linux 服务器）

把课程 4 的假数据换成真的：AF_PACKET 抓 SYN 包 → 五元组 → 匿名化（HMAC，文档 §9）→ 广播。
服务器已经备好（Alibaba Cloud Linux 3，2C4G，已清理出 24G 空间）。

## 课程 7：Stress 模式

写一个 `pulse-loadgen`：一台机器压出 10K WebSocket 连接，看内存和 P99。
这时你会真正撞上：有界队列、backpressure、慢消费者断开（文档 §23）。

## 课程 8+：二进制协议 / WebGPU / eBPF

文档 Phase 2-5 的正餐。到时候再说。

# PULSE 手写学习路线

这是一份练习安排，不是要求一次读完的知识清单。先完成眼前一课，再根据结果调节难度。按每次 20–45 分钟设计；遇到新概念可以拆成两次，不追赶日历。

## 1. 从你的实际卡点出发

历史对话中，你已经问过并接触了这些关键问题：

- `mousemove` 从哪里产生，为什么注册一个函数就能接到事件。
- `ServeHTTP` 没有显式调用，为什么收到请求后它会运行。
- 一条连接与 `Session` 怎样绑定，`&Session`、`*Session` 和值拷贝的区别。
- `go writePump(...)` 为什么不阻塞后面的读取；channel 怎样连接广播和网络发送。
- 为什么 20Hz 网络更新可以用更高频率绘制，以及接收时间如何用于插值。

因此学习主线是“事件 → 状态 → 消息 → 所有权 → 绘制 → 生命周期”。暂时不同时学习 Go 全部语法、前端框架、WebGPU 和 eBPF。

## 2. 每次练习怎么做

1. **回忆 3 分钟。** 不翻答案，画上一次的调用链或口述一个函数契约。
2. **预测 5 分钟。** 给定一组输入，先写输出；猜哪一处改错会让页面失效。
3. **手写 15–25 分钟。** 一次改一个行为，先写中文函数注释，再写函数体。
4. **验证 5–10 分钟。** 跑必要检查，并用一个正常例子和一个反例验证。
5. **记录 3 分钟。** 写实际结果、错误原因和下一次能否独立复写。

时间只是切分任务的参考。连续试两次仍无进展就请求下一层提示，不需要为了“独立”硬卡固定十五分钟。

## 3. 提示逐层给

- **提示 1：定位。** 指出哪个函数/哪条数据链出了问题，问你该观察哪个变量。
- **提示 2：约束。** 给输入输出、边界和伪代码，不给完整可粘贴实现。
- **提示 3：局部示范。** 只写一个小函数或几行关键逻辑，并解释每行的作用。
- **提示 4：完整示范。** 你明确要求时提供；随后换一个小题让你不看原答案实现。

“看懂了示范”记为看懂，不立即记为独立完成。助手不要故意藏着基础语法不讲，也不要用一大段完整代码替代你的练习。

## 4. 课程顺序与闸门

### 第一段：让已有代码真正连起来

- L0：画调用链，定位自动发生的回调。
- L1：接通插值绘制，这是当前首个实际任务。
- L2：手算并重写插值的小函数，补边界与纯函数测试。
- L3：让采样与缓冲有明确上限，理解网络频率和绘制频率的分工。

通过条件：能独立解释一次鼠标移动怎样到达另一页的 `ctx.arc`，并用测试及双页面观察证明插值结果被消费。

### 第二段：独立扩展一条小消息链

- L4：从协议开始完成一次点击脉冲。
- L5：通过快照练习 Go 值、指针、锁和 channel。

通过条件：不照着 cursor 全盘复制，能说明 pulse 为什么需要事件 ID、独立视觉生命周期和限频。

### 第三段：让功能经得住断线与错误

- L6：补连接失败、退出、重连和输入边界。
- L7：实现 idle/focus 与一项真正可解释的指标。

通过条件：能构造坏输入、写失败和重连的反例，说明谁负责清理每项资源。

### 第四段：理解性能和交付

- L8：小规模本地负载与指标解释，再决定是否需要聚合/AOI。
- L9：读懂构建、部署、健康检查和回滚流程。
- L10：用独立传感器把一次真实主机入站事件接到 Host Radar；L6 通过后可与 L8/L9 协商顺序。

通过条件：能区别空闲连接数、活跃发送连接数、消息吞吐、应用 RTT 和画面延迟；能解释一次 push 的后果。

按依赖进入下一段。Host Radar 在可靠连接之后做一个小闭环；10K 连接、二进制协议、WebGPU 和 eBPF 是后续专题，不作为眼前接通插值的门槛。

## 5. 防止只会跟写

每完成一课，在下一次开始前做一个 5–10 分钟迁移题。例如：

- 学完鼠标归一化，用键盘方向键更新同一个 `pending`，不改服务端协议。
- 学完位置插值，用相同的 `lerp` 计算透明度，再解释哪些部分可复用。
- 学完快照，设计一次“取出快照后修改原对象”的检查，观察两者是否一起变化。
- 学完 pulse，画出 `focus` 的消息链再写实现，先区分事件与状态。

迁移失败就回到对应概念练一次，不重做整个项目。

## 6. 给助手的作业格式

```text
课程：L1 插值接线
目标：让远程点实际使用 samplePosition 的结果
我的理解：收到的坐标进入缓冲，draw 选择较早的渲染时刻
我改的文件/函数：static/app.js / draw
我的预测：自己的点不延迟，远程点在两个样本间平滑移动
实际结果：填写观察或错误
我卡住的地方：填写具体表达式/调用关系
需要的帮助：提示 1 / 提示 2 / 局部示范 / review
```

## 7. review 的顺序

先检查“功能结果是否正确”，再追踪输入到结果的整条链，接着看错误边界、注释和职责。不要先用命名、文件长度或复杂设计打断当前核心练习。

助手每次最终只给：本课已成立的证据、一个最重要的问题、下一步的小任务。长期计划留在文档里，不在每轮对话中重新布置所有课程。

## 1. 下一版本只完成一个目标

> 关掉页面再回来，我的岛还在；朋友打开链接，到的确实是我的岛；他能浇水，却不能改乱我的布置。

用户认可当前界面已经可以继续推进。暂时固定潮汐群岛、粒子海面、镜头纵深、系统鼠标和远端指针的方向，只修复阻挡使用的 UI 问题。后端建设服务于上面这段体验，不以重构文件数量或引入组件数量衡量进度。

这个版本面向少量真实用户试用，不声称已经是大型社交平台。每个人最多一个个人岛；所有岛先公开可访问；个人身份先在同一浏览器内保持。以后再接跨设备登录、密码岛、权限邀请、更多物件和博客导入。

三件事分别验收：功能是否实现、是否有验证证据、用户是否理解关键逻辑。不能因为 AI 写完，就把学习状态标为“已掌握”。

`islands.go` 里仍是三个固定示例岛。Session 是连接身份，刷新与重连可能得到新编号；没有稳定用户、owner 关系和个人岛屿存储。

前端仍直接使用固定 `ISLANDS`；收到服务器数据并不等于渲染已经改为动态岛屿。迁移必须检查 welcome → 数据更新 → 几何构建 → 标签 → 命中 → 水动作 target 的整条路径。

## 3. 执行边界与默认决定

**顺序固定为 G0 → G1 → G2 → G3 → 小范围真人试玩。** 每个包都要有独立可演示结果；一个包允许拆成几轮对话，未验证前不自动宣布进入下一包。

本轮计划中的默认决定：

- 继续 Go 单服务 + Vue 3/Vite 界面 + 普通 JavaScript 粒子引擎 + 已有 WebSocket。旧的不迁框架默认已被用户本轮明确授权覆盖；沿 16 的边界开发，不另起前端。
- G0 先在现有 JSON 路径修正写入语义；G1 开始将身份、岛屿和内容纳入 SQLite 事务存储，避免逐个新增相互不同步的 JSON 文件。
- 当前部署采用 `CGO_ENABLED=0` 构建。执行 agent 选驱动时必须验证 Go 1.25、Windows 开发、Linux 无 CGO 构建三者兼容，锁定版本；本文不预设未经验证的驱动版本。
- 没有新证据，不引入 Redis、消息队列、微服务、分片数据库或实时协同编辑框架。
- 保留临时访客入口；先用服务器签发的持久会话识别同一浏览器中的同一用户。不把昵称、localStorage 的 owner 标记、URL 参数当凭证。
- 访问别人岛屿不会自动创建自己的岛。只有点击“创建我的岛”才创建；同一用户最多一个，重复提交返回同一个岛。
- 第一个版本只支持主人布置、所有访客照料。公开可访问不等于公开可编辑。
- 浇水仍是轻互动：不会枯萎，不按天打卡，独自也能开花；不新增经验值、排行榜、货币和强制每日任务。

需要另行讨论的变化：第三方登录方式、跨设备恢复、私人岛、付费功能、公开部署与迁移窗口。不得在没有这些答案时重做 G0，或阻塞 G1 中已明确的独立工作。

## 4. 用户应该经历的完整过程

### 4.1 第一次从首页进入

展示当前视觉氛围，提供“创建我的岛”与“先去看看”。游客浏览不需要先填写一整张注册表，也不因打开页面就在数据库生成一座岛。

用户选择创建，服务器建立或复用浏览器身份，在事务内创建岛和默认植物，然后跳转到 `/islands/{islandId}`。网络慢时按钮显示“正在准备”，重复点击不会重复建岛。

默认岛名可以是“我的小岛”，创建完成后可改。视觉上显示自己的岛，其他岛可以主动探索；不重新设计新的登录大屏或 UI 主题。

### 4.2 再次进入

同一浏览器保留有效凭证时，首页提供“回到我的岛”。刷新、关闭标签页、正常重启服务后，应恢复同一岛、植物状态与布置。

这个阶段的身份边界要明确：清除 Cookie、过期或换浏览器后，不能保证恢复岛主权限；公开岛链接只能找回可访问的页面，不能恢复编辑权。创建时以简短说明告知“暂时通过此浏览器保存管理身份”，不要宣传跨设备账号能力。正式扩大使用前再接可恢复登录；不要私自提供不安全的“输入岛名认领”。

### 4.3 邀请与来访

主人点击“邀请朋友”，复制当前岛的稳定公开链接；不生成管理员凭证，不新开自己的页面。复制失败时展示可选择的链接，让用户手动复制。

另一个浏览器或另一台设备打开链接，直接落在指定岛屿。界面显示岛名、主人昵称，以及“来访中”等轻量上下文。访客不用先创建岛就能浇水。

主人不在线也可以访问和照料，之后主人看见最近照料记录。只在访客真正进入此岛时提示主人“有人来到岛上”，不把全站任意连接都提示为自己的客人。

不存在的岛显示“没有找到这座岛”和回首页入口，不静默跳到示例岛，不在 GET 请求中创建新岛。

### 4.4 浇水与回应

靠近植物显示可照料提示。用户点击后出现短暂等待；收到服务端提交成功的结果，才改变共享生长状态，并播放水滴。

同岛其他人看到同一次动作。六秒内不同稳定用户照料同一株时可显示共同反馈；同一人开两个窗口不能算两个人共同照料。

失败时明确说明“未能保存，请重试”；网络断开只能浏览已知快照，不能显示假的保存成功。重试使用原请求 ID，不能因为回复丢了再加一次成长。

### 4.5 布置与保存

只有主人看见“布置我的岛”。先支持移动现有植物与修改岛名，验证成功后最多补两类简单装饰；不做完整建造编辑器。

进入布置模式后，拖动植物改变本地草稿，海面仍可拖动画面。释放后显示“有未保存改动”，点击“保存布置”提交；取消恢复最后一次服务器快照。

保存成功后退出或继续编辑，访客实时看到新位置。只播放水滴的动画属于瞬时效果，植物位置与生长属于持久状态，二者不混在同一套逐帧上报里。

## 5. 功能包与验收

### G0：一次“已保存”必须可信——当前下一包

**交付范围：** 修复现有植物写入的一致性、失败恢复与水动作确认。保留当前 UI，只补失败提示和必要的等待状态。不同时做账号和 SQLite 迁移。

实现步骤：

1. 阅读 `Garden.Water → persist → main.go water → plant → app.js`，确认实际调用者和并发边界。
2. 为保存器提供一个狭窄的可注入边界，让测试能精确控制“第一次保存暂停、第二次请求到来、写入失败”，不靠随机 sleep 碰运气。
3. 单进程版本采用串行提交：在 Garden 级别持锁，基于旧状态构建候选快照，完成保存后再发布为新内存状态。失败丢弃候选值。不要持有全局 Hub 锁做磁盘 IO。
4. 去重、冷却只在动作被成功接受后记账；重复已成功请求返回原结果或明确确认，不能仅丢弃，让前端等到超时。
5. 增加带 `requestId` 的成功/失败结果。先在现有 water v1 中复用 `eventId`，下行确认回带该 ID；已有广播继续携带快照。前端只有匹配当前请求的结果才能解除等待。
6. `not_found`、`cooldown`、`save_failed`、协议错误要有可区分结果；服务端日志记录错误码和请求 ID，不把本地文件路径与内部异常直接暴露给普通用户。
7. 文件不存在允许初始化；读取错误、解析失败与不合法内容必须报错并保留原文件。禁止下次浇水覆盖损坏文件。可选择启动失败并记录原因，不能默默清空个人数据。
8. 说明临时文件、替换与崩溃耐久的范围。原子替换不等于断电不丢；文件同步、目录同步与平台差异按实际部署系统实现并写清测试限制。

验收：

- 正常一次浇水：响应、内存、磁盘与两端显示一致。
- 保存失败：内存版本与阶段不变；不广播成功；用户能重试。
- 两个并发请求：后一个成功提交后，重启恢复的版本不能倒退；用测试屏障控制顺序。
- 成功后回复丢失，再发相同请求 ID：不再次成长，不重复播放一次性效果。
- 损坏文件：启动明确失败或进入明确不可写状态，原数据字节不被修改。
- 现有连接/插值测试仍通过，故障不会卡住所有指针广播。

G0 的重试保证限定为同一活连接与有界去重缓存内。刷新/重连/进程重启后的去重在 G1–G2 纳入持久操作记录；不要把当前 64 条内存缓存描述成永久去重。

**本包学习点：** 保存失败后，候选快照属于谁？用户只写或解释一个 `persist` 返回错误的反例：前后 Snapshot 必须相同。第一级提示：观察 `care++` 相对于持久化成功发生在什么时候。估计 20–30 分钟，可单独安排，不挡住 AI 修复。

### G1：建立稳定身份与一人一岛

**交付范围：** 一个浏览器身份能创建并再次进入同一座个人岛，岛名、默认物件和植物状态能持久化。暂时不开放复杂装修。

实施顺序：先定义领域关系与事务，再接身份入口、创建和动态加载，最后迁移固定数据。

必须明确三种 ID：

- `userId`：服务器定义的稳定用户，拥有岛、产生照料记录。
- `connectionId`：一次 WebSocket 连接，控制在线状态、插值缓冲与清理。断开即失效。
- `islandId`：一个稳定空间，出现在链接、查询与数据外键里。不是昵称散列，不等于用户 ID。

浏览器身份建议：服务器产生高熵随机凭证，Cookie 仅存凭证，数据库保存其不可逆摘要、所属 userId、有效期与撤销状态。生产 Cookie 使用 HttpOnly、Secure、SameSite=Lax、Path=/、不指定 Domain。开发环境的 HTTP 例外必须显式配置；生产错误配置应启动失败。初版可采用 30 天有效期并明确失效边界，不借此声称永久账号。

HttpOnly 不代替鉴权，SameSite 不代替 CSRF 防护。HTTP 写入校验受信 Origin 和会话绑定的 CSRF token；WebSocket 握手检查受信 Origin、解析服务端会话，每个写动作仍进行资源级授权。localhost 白名单只用于开发配置。具体属性语义参考[MDN Cookie 文档](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)，WebSocket 边界参考[OWASP](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html)。

访客身份可以在第一次需要互动时建立；公开 GET 不自动授予编辑权、不创建个人岛。用户点击“创建我的岛”后，通过 owner 唯一约束和事务保证同一用户并发创建仍只得到一座岛。昵称只用于显示，不参与鉴权。

启动顺序固定为：公开岛查询 → 查询当前身份 → 需要加入实时在场时建立或复用访客会话 → 获取会话绑定的 CSRF 信息 → WebSocket 升级。建立会话未成功前不发送浇水。已有连接在凭证过期或被撤销后也不能继续写入；每次写操作核对会话有效性，拒绝后提示重新建立身份。

SQLite 数据建议采用最小实体：

- `users`：id、displayName、createdAt。
- `browser_sessions`：凭证摘要、userId、expiresAt、revokedAt。凭证不能下发进公开 DTO 或日志。
- `islands`：id、ownerId、name、sampleFlag、seed、geometryVersion、几何参数、layoutVersion、stateVersion、createdAt；个人岛 ownerId 非空且唯一，历史示例岛允许 ownerId 为空，不能被客户端认领。
- `objects`：id、islandId、kind、localX、localY、rotation、props；当前每岛默认一株植物。
- `plant_states`：objectId、care、lastUserId、lastDisplayNameSnapshot、lastAt；不要再靠三个数组下标关联岛屿。
- `operation_receipts`：userId、requestId、请求摘要、目标与动作类型、结果版本、结果摘要、createdAt；用于 G2 的可靠重试。

这些是逻辑实体，不要求为每张表预建一套空 Service/Repository 层。实现使用参数绑定与约束；schema 必须有版本迁移记录。一个写事务完成业务变化与操作回执，提交成功后才发事件；读缓存不是新的权威源。采用 SQLite 是本项目单实例阶段的选择，不是为所有规模推荐同一个方案；事务能力参考[SQLite 官方说明](https://www.sqlite.org/transactional.html)。

动态岛屿加载必须替代固定 `ISLANDS` 的生产依赖：服务器返回 seed、geometryVersion 和几何参数；渲染器接收岛数据并重建受影响缓存。前后端不能各自猜测种子或半径。现有几何函数、相机、插值与粒子效果继续复用。

验收：同浏览器刷新/重新开页/服务重启后 userId 与 islandId 保持；不同浏览器身份不共享所有权；同用户两页并发创建只产生一个岛；伪造 ownerId 被忽略或拒绝；删除 Cookie 后公开链接仍可读但不能编辑；加载任意存储岛而非只加载 origin 成功。

G1 至少把自己的 `/islands/{id}` 加载和刷新接通，形成可演示的创建闭环。G2 再完善其他用户的邀请入口、访问上下文、岛级订阅和在场统计；不要为了等待 G2 而让 G1 创建后无页面可进入。

**本包学习点：** 为什么 userId 不能用 connectionId？用户用两次连接和一次刷新解释岛的归属，再补“伪造 ownerId 不能认领别人的岛”的反例。第一级提示：服务器从哪里取得操作者身份？

### G2：真实拜访、岛内在场与可靠浇水

**交付范围：** 稳定岛屿链接、复制邀请、访客直接访问、当前岛的真实在线用户、主人离线时仍可照料。

用 `/islands/{islandId}` 作为规范页面路径。后端能直接返回页面壳，前端从路径读取 ID，再查询真实空间；刷新深链接不能 404 到静态服务器。旧 `/?visitor=1` 可以忽略该参数后进入首页，但不把它保留为身份判定。

“邀请朋友”复制 `origin + 规范岛路径`，不携带会话凭证。复制失败展示只读文本。来访者有自己的 userId；不能因为链接由主人发出就继承主人身份。

为连接明确增加“当前订阅的岛”，不要用鼠标恰好划过哪个几何边界来决定访问权限。几何命中可继续用于地形高度，但不代表用户订阅了另一个岛。G2 最小实现允许切岛时关闭旧 WS 并携带新 islandId 建连，复用现有 generation 隔离；无需首轮实现复杂多岛订阅。

在场、指针、plant 与布局变化只广播给目标岛订阅者。初版每个连接订阅一座岛；保留最多 128 总连接的基础限制，并给岛内订阅设置有界预算与“人数已满”提示。全站指标留在诊断区。

人和窗口分开：在线人数按当前岛不同 userId 统计；同一用户多个连接可保留各自指针，但标明同一名字，不把新窗口提示成陌生客人。首个连接进入才产生用户级到访，最后一个连接离开才产生用户级离开；一页关闭不能让仍在线的同用户消失。

浇水由服务端检查身份、当前订阅、植物归属与冷却。共同照料比较两个 userId，且前一个用户当前仍在同一岛；主人离线不影响普通浇水。每用户的冷却跨窗口共用，不能靠多开页面绕过。

请求 ID 使用随机唯一值，稳定保留到动作结果明确。服务端持久回执按 `(userId, requestId)` 去重并比较请求摘要；同 ID 换 target/payload 必须返回冲突。先查询已成功回执，再执行冷却与重复动作判断；已经提交的请求即使重连也能拿到确认。

初版回执与客户端重试窗口统一为 24 小时，有界清理；过期客户端不自动重放，转为刷新状态后由用户明确发起新动作。客户端发包次数、排队长度和超时要有上限。不要声称网络上的绝对 exactly-once；承诺的是约定时间窗内同一用户同一操作不重复生效。

验收：复制链接由第二个浏览器打开，进入正确岛；A 岛用户收不到 B 岛光标/照料/布局；同用户两页不触发共同浇水；两位真实用户能触发；旧 WS 回调不污染新岛；断线重连恢复当前岛和快照；已提交但丢确认的请求重试不再次成长；来访时不要求创建个人岛。

**本包学习点：** 两个窗口和两个人有什么不同？用户补一条同 userId、不同 connectionId 的共同照料反例。第一级提示：观察当前 `together` 比较的是哪一种 ID。

### G3：让岛上布置带有自己的选择

**交付范围：** 岛主改岛名、移动植物、保存/取消、访客实时看到保存结果。先实现这两种修改，再考虑石头或灯等两类白名单装饰。

进入编辑模式才接管物件拖动；正常模式仍用于漫游和照料。建立清楚的状态：浏览 → 编辑未改动 → 编辑有草稿 → 保存中 → 保存成功或失败。Esc 取消拖动，取消编辑恢复快照；切岛/离开时有未保存草稿，要让用户选择保留当前编辑或放弃，不偷偷保存。

位置存岛屿本地坐标，不存屏幕 px。物件投影与命中继续复用世界几何。落点必须在服务端认可的可布置区域；越界时显示无效位置，释放则回到有效草稿位置。客户端校验便于反馈，服务器必须重新校验。

使用 `layoutVersion` 乐观并发控制。编辑器打开时记住基础版本，保存携带 expectedVersion；事务中版本不匹配返回冲突与最新快照，不覆盖别的窗口保存。`stateVersion` 可随浇水与布局变化更新，但一次浇水不能让未冲突的布局编辑无故失效。

保存中禁止重复提交同一草稿，失败保留草稿并显示重试；使用同一请求 ID 重试。返回成功后更新服务器快照和本地基础版本，再通知该岛访客。其他窗口的草稿不被广播自动覆盖，提示“岛上的布置已更新”，让用户重新加载后再应用自己的修改。

初版限制建议：每岛最多 12 个物件；名字 1–24 个 Unicode 字符；只接收已定义 kind 和有限数值，拒绝 NaN、Infinity、未知物件字段、任意 HTML/脚本。具体坐标范围由几何判定给出，不散落多份魔法数字。

验收：同一布局在两种视口中位置一致；刷新与重启后位置不丢；访客直接调用保存接口返回 forbidden；旧版本写入冲突可恢复；浇水不移动植物或覆盖布局草稿；拖动取消没有服务端写入；至少完成一台手机或触屏设备的真实拖动验收后才宣称支持触控编辑。

**本包学习点：** 用户写一个旧 layoutVersion 保存不能覆盖新布局的反例。第一级提示：两个标签页打开同一布局，谁先保存，另一个应收到什么？

## 6. 接口与消息草案

以下是待实现的契约，不是已经存在的接口。执行 agent 可沿现有代码调整命名，但必须同步文档、客户端、测试，不能同时维护几套同义身份或岛 ID。

### 6.1 HTTP 边界

- `GET /api/me`：返回当前身份摘要和 ownIslandId；无有效凭证返回匿名状态，不因 GET 创建个人岛。
- `POST /api/session/guest`：建立或复用浏览器身份并签发 Cookie。建立身份不等于创建岛；端点需来源校验和限流。
- `POST /api/islands`：只接受岛名等允许输入，从服务端身份绑定 owner；幂等返回该用户唯一岛。
- `GET /api/islands/{id}`：返回公开岛名、owner 显示资料、几何、物件、植物状态、版本和当前用户 capabilities；不返回凭证或私人资料。
- `PATCH /api/islands/{id}/layout`：owner 校验、expectedVersion、requestId、受影响物件及可选新岛名，在一个事务中提交。
- `GET /islands/{id}`：页面壳；岛不存在由 API 与页面统一展示明确的不存在状态。
- `GET /ws?islandId={id}`：携带浏览器 Cookie 升级，检查 Origin、身份和岛是否可访问，订阅指定岛。

HTTP 结果采用明确状态：401 身份无效、403 无权修改、404 不存在、409 版本或请求 ID 冲突、422 数据越界/非法、429 限流、503 暂不可用或提交失败。会话建立与 CSRF token 分发的具体端点可以合并，但客户端启动顺序必须可解释。

### 6.2 水动作示例（G2 目标协议）

```json
{"type":"water","v":2,"requestId":"example-request-uuid","islandId":"island-example","objectId":"plant-example"}
```

客户端不提交 userId、ownerId、care 或“是否共同浇水”。服务器从连接身份和订阅取操作者，查询 object 的所属岛，提交后返回相关联的结果。

```json
{"type":"action_result","requestId":"example-request-uuid","ok":true,"islandId":"island-example","stateVersion":8,"duplicate":false}
```

```json
{"type":"action_result","requestId":"example-request-uuid","ok":false,"code":"cooldown","retryAfterMs":900}
```

以上 ID、版本与时间为文档示例，不是真实用户或流量。成功结果与对应状态增量必须定义清楚：可以同包携带快照，也可以发送 `island_state`；但任一方消息先到时都不能重复加阶段。UI 只能从权威状态赋值，不能“收到成功加一、收到广播又加一”。

水消息从现有 v1 升到 v2 时做明确兼容策略。最小方案是前后端同一版本发布，旧客户端收到 `reload_required` 并停止旧写入；不能静默按新协议解读旧数组下标。G0 的 v1 确认机制是先修问题的过渡，不是并行保留两个长期协议。

### 6.3 快照与在场

welcome 至少包含 protocolVersion、connectionId、当前 user 摘要、订阅 islandId、islandState、该岛 connections 和服务端 capabilities。

指针继续使用现有世界坐标 wx/wy 契约与服务端地表高度。布局使用岛屿局部坐标，通过岛变换转换为世界坐标，两种坐标名字与单位要写在注释里。不要为了增加岛屿身份重写已稳定的 Hermite 插值。

客户端的版本比较必须以 islandId 分开；从 A 岛版本 100 切到 B 岛版本 3，不应因为“版本更小”拒绝 B 岛快照。重连与切岛时清理旧插值、旧动态效果和旧连接回调。

快照与订阅建立要避免消息缝隙：先在同一同步边界登记订阅并取得快照，将 welcome 排在后续增量前发送；或定义序列缺口检测与重取快照。不要读完快照、过一会才订阅，造成中间的一次保存永久遗漏。

保存成功但广播失败时，持久状态仍然有效，重连快照必须能补回。实时广播不是第二次数据库提交，也不要求因某个慢连接失败而回滚已经完成的保存。

## 7. 世界与布局：先稳定地址，不扩张无限地图

第一阶段每座个人岛是独立可寻址场景，仍有海面、纵深和拖动感。直接拜访可以使用连续镜头转场；不要求把全部用户岛屿都放进一张永久无穷平面。

如果当前场景仍展示示例邻岛，必须标注示例，不显示伪造人数。跨岛探索入口先返回少量公开岛信息，选择后加载目标场景。私人空间未来的发现规则另行设计。

相机移动属于本地状态；指针移动属于短暂在场；植物生长和布置属于持久内容。三者分别处理，不保存每一帧相机位置，不把海面粒子本身写进数据库。

## 8. 存储迁移与发布边界

G0 保障当前 JSON 不因保存失败产生半成功状态。G1 引入 SQLite 时，要迁移而不是悄悄放弃已有记录。

迁移步骤：识别旧 JSON → 验证结构 → 备份并记录来源 → 事务中建立明确标为 sample 的三座旧示例岛及植物 → 记录 schema/migration 版本 → 校验数量、阶段与最近照料时间。旧临时 Session ID 只作为历史显示文本保存，不转换成新用户或岛主。

旧样例状态不能自动归给第一个进入网站的人。新用户创建新个人岛。迁移重复执行必须幂等；失败回滚新库变更并保留源文件；不得删除原始 JSON 来掩盖失败。

数据库路径用配置指定到部署目录之外的持久数据目录，不依赖不明确的工作目录。实际服务器的工作目录、运行用户、目录权限、备份方式需要读取部署配置验证，本文没有访问服务器。

当前 `.github/workflows/deploy.yml` 仅显示 vet、Linux 无 CGO 构建与远程部署脚本调用；不能据此推定它执行了全部测试或保留数据。G1 需要确认驱动构建兼容，发布前加入相应行为检查；支持 CGO 的 CI 上执行 race 检查，说明 Go race 检查不等于证明所有落盘顺序正确。

发布只在用户明确授权后进行；main push 会自动部署。上线前做备份、迁移演练、深链接刷新验证、两台设备拜访、权限拒绝与服务重启恢复。生产如果无法验证，要明确标记未验证。

回滚应用不一定能回滚数据库 schema。发布说明必须记录旧二进制是否能读新库；不兼容时停服并按备份恢复，不让新旧格式双向乱写。数据库热备份需使用受支持的一致性方法，不能只复制正在写入的主文件而忽略日志状态。

保持现有职责：`world.js` 渲染/投影/命中，`app.js` 启动/网络/界面状态，`pure.js` 可独立测试的计算，Go 处理授权、提交和广播。身份与存储职责出现后再按实际边界拆文件，不先造十层空目录。

每个函数、方法和业务回调遵守[中文注释 Skill](../.agents/skills/comment-convention/SKILL.md)：用途、输入单位、失败结果、是否修改状态；锁、文件、连接、计时器的归属与清理必须说明。不要逐行翻译代码，也不要把未来方案写成已实现的注释。

保护手写成果，先看 diff；用户说“提示”只给分级提示，不替换整段代码。用户授权实现时，AI 完成 UI 接线、协议结构、重复工作、测试与文档，只留一项关键练习。按[陪练 Skill](../.agents/skills/handwrite-coach/SKILL.md)给提示，主要实现分工以根目录 AGENTS.md 与本文件为准。

## 10. 验证策略与完成定义

测试针对契约与失败链路，不为每行 CSS 写测试，也不复制实现算法后只比较两份同样的代码。

- 单元：状态候选提交、几何边界、布局版本、身份解析与权限判定。
- 存储集成：临时数据目录；提交失败、并发写入、事务回滚、迁移幂等、重启恢复。
- HTTP/WS 集成：真实测试服务与两个独立身份；订阅隔离、错误关联、跨连接重试、同用户多连接、权限拒绝。
- 浏览器：从真实入口创建/访问/复制链接/照料/布置/保存/刷新，检查最后消费的 UI，而非只看返回 JSON。
- 真人与生产：两位用户、不同设备实际来访。两个测试窗口只能证明程序联动，不能证明社交吸引力。

至少检查这些反例：同用户多开、陌生人改 ownerId、错误岛的 objectId、旧版本覆盖、新旧岛版本大小不同、提交成功后断网、磁盘失败、损坏存储、断线后旧回调晚到、拖动取消、脚本字符昵称、非法数值坐标。

每个包交付必须包含：用户可见结果、关键调用链、检查命令及实际输出摘要、未验证范围、数据兼容变化、一个学习点、唯一下一步。仅文档更新不能写“功能完成”，仅测试通过不能替用户决定“界面满意”。

## 11. 现在暂缓的事项

暂缓新的海面风格、房屋或岛屿主题重做、全套角色系统、自由地形建造、私人岛密码、好友聊天、完整植物养成、公开内容推荐、GitHub 写回、无限区域、分布式 AOI 和大型压测平台。

这不表示这些想法被否定。遇到可测量的卡顿或使用障碍仍然修复；但必须说明触发场景与影响，不以“顺便优化”为由开启另一轮整体 UI 重构。

旧 L0–L10 是知识索引。点击脉冲和可靠连接已有实现，不再按 A/B 旧顺序重新开发；Host Radar 保留独立兴趣分支，不作为个人岛屿的前置任务。

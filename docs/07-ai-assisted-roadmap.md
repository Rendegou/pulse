# PULSE：AI 协作开发与关键能力训练

更新：2026-09-07。源码核对基线：`4946e28`。本文件决定新的执行顺序；L0–L10 改为按需查阅的课程库，不再逐课解锁产品。

## 1. 这次为什么调整

你已经借助另一个 agent 推进到 L3c。当前代码包含远程插值绘制、Hermite、播放段切线缓存、归一化、双上限缓冲和发送预算。继续从 L1 接线、逐个手写简单函数，会重复已经完成的工作。

新的目标有两个：持续做出可以体验的产品；逐步具备定义行为、理解状态、修改关键逻辑、用证据定位问题的能力。不用手写行数评价学习，也不用 AI 生成的功能数量评价掌握程度。

本次仅调整文档与协作安排，不自动启动后续功能开发，也不授权推送或部署。

## 2. 分工：让 AI 做完整交付，让你抓住关键部分

**AI 默认完成：** 常规 HTML/CSS、重复协议结构、按已定契约接线、测试脚手架、样例数据、机械重构、注释与文档同步、运行检查、整理失败证据。简单不代表可以省略校验；把这些工作委托给 AI 后仍需验收。

**你保留决定权：** 体验目标、事件与状态的区别、数据归谁所有、失败后怎么办、验收是否符合预期。每轮只选一个关键练习，不要求你为每个函数重新实现一遍。

**适合亲手写的部分：** 一个状态转换、一个边界校验、一个坐标变换或一个反例测试。适合共同审查的部分包括并发清理、重连隔离、鉴权和存储冲突；这些不能因为代码短就当成机械工作。

你只说“继续”时，执行 agent 读取进度中的下一包，在该包内先推进 AI 部分；给你一个明确的学习点。你说“提示/一点点”时，只提示当前问题。你说“完整实现”时，AI 完成实现，之后用一个小改动检查理解，不用教学模式拒绝帮助。

## 3. 每轮怎样加速，又怎样防止只会点接受

1. **约 5 分钟定契约。** AI 用一句用户行为说明本轮目标，给出正常结果、一个失败例子和改动范围；只问无法从源码推断的关键问题。
2. **AI 推进功能包。** 实现已经明确的部分，完成相应检查。不要为了把工作留给你而在主程序留下空函数或故意失败的测试。
3. **约 20–30 分钟练一个核心点。** 你选择实现一个小函数，或独立写一个反例并解释为什么能抓错；已熟练的普通接线直接跳过。
4. **约 5–10 分钟讲解与验收。** 沿“输入 → 状态 → 消息 → 消费端”解释关键变化；你实际操作一个正常场景和一个异常场景。
5. **下一轮约 5 分钟迁移。** 换一组数据或一个相近场景，确认你能改动。不会就定点补练，不回滚产品、不重学整课。

这些是安排时间的参考，不是完成期限。学习练习没结束时，AI 可以继续不依赖它的工作；生产代码可以采用示范实现，学习状态仍记“待迁移”。产品验收未通过则不能标记交付完成。

一个功能包可以跨多次会话；每次收尾留下可运行状态、实际检查结果和唯一下一步。提交按有意义的功能范围组织，不为每几行代码分一次提交。

## 5. 接下来的功能包

### A：两个人可以打招呼——当前下一包

**演示结果：** A 点击画布，A/B 各出现一次脉冲，效果消失，断线重连不重放旧点击。保持当前界面。

**AI 负责：** pulse 前后端完整接线、中文注释、有界视觉效果和去重缓存、消息校验、必要测试、教程更新；把 L4 与必要的 L6 输入边界合在一次功能交付中，不再切成三次等用户抄写。

**拟定契约：** 客户端 `{type:'pulse',clientEventId,x,y}`；服务端以当前 Session 身份生成 `eventId` 并广播；ID 有长度上限，x/y 必须存在、非 null、有限且在 0..1。第一版只在服务端接受后播放，不做本地乐观脉冲。重试旧事件不属于本包。

**本包必做保护：** 读取大小上限、文本消息与类型白名单、pulse 每连接限频（初设平均 2/s、突发 4）。这些与功能一起由 AI 完成，不为了提速延期到上线之后。

**你只练一个点：** 在 `readPump` 的解析路径附近，为拟定的 `validatePulse` 校验逻辑写一个“零坐标合法、缺字段非法”的行为测试。函数签名由执行 agent 结合实际拆分确定，不能要求你先学完整测试框架。

**输入/结果：** `{x:0,y:0}` 接受；缺 x、x=null、x=-0.1 拒绝。反例是 Go 数值零值会把“没传”误认成合法 0。提示 1：先观察 JSON 解码后还剩不剩“字段存在”的信息。

**交付证据：** 两个实际 WS 客户端收到各一次事件；非法输入未广播；效果及去重集合有界；页面确认圆环产生和过期。测试客户端收到了 JSON 不等于页面已经画出来。

### B：关闭、断线、慢连接后能恢复

**依赖：** A 可演示。暂不增加房屋写入等持久状态。

**AI 负责：** welcome/writer 失败联动关闭、单一注销 owner、心跳与超时、重连 generation 与单一定时器、连接和 cursor 预算、队列满后断开慢消费者、最小健康/版本检查与本地测试入口。按失败路径分小步完成，最终交付一个完整可靠性包。

**你只练一个点：** 根据真实代码画出“writer 失败 → 唤醒 reader → 注销 → leave”的资源释放链，再修改一个故障注入用例，证明在线数会回落。锁/close 的关键改动必须能解释，不能仅凭测试绿灯接受。

**验收：** 正常连接持续可用；失败连接最终回收且不重复 leave；重连不受旧回调污染；无并发发送到已关闭 channel；`go test -race` 在支持环境执行并说明覆盖范围。发布所需 CI 检查跟随本包补入，不必等到旧 L9 全课结束。

### C：选择一个产品方向，不同时铺开两个平台

A/B 是共同基础。用户提出“是否先完成原版以打好基础”后，本次规划建议采用 A → B → C-World；Host Radar 不作为博客世界的前置课程。理由是连接、消息和生命周期可以直接复用，而主机抓包属于独立专题。这个顺序是助手建议，可按后续体验调整，不代表用户已决定放弃原版或博客仓库已接入。

**C-World，推荐的可见成果：** 一个固定街区、两间房、两篇文章、两名真实访客可以一起逛。先用明确标记的示例文章或用户提供的真实内容；不虚构博客同步。

- AI 做相机平移缩放、房屋布局、文章阅读入口、真实 Presence 接线、窄屏和键盘入口。先把文章放在普通可选择文本的 DOM 阅读区，保留稳定文章链接。
- 指针必须从当前屏幕 0..1 坐标升级成明确的世界坐标/区域坐标契约，不能把不同视口的归一化位置直接当世界位置。前后端校验与插值输入要同步调整。
- 你只练 `screenToWorld` 一类纯函数：相机移动后同一房子的世界坐标不变；两个人相机位置不同仍能指向同一扇门。输入、单位、缩放原点由 AI 先写清。
- 验收：双方能找到同一房子、读到同一篇文章；一人平移不移动另一人的相机；指针落在正确世界位置；文章可直接打开。此包不做公开自由建房、账号或无限区域。

**C-Radar，可替换分支：** 若你选择先完成原 PULSE，按 L10 接通显式 fixture → 独立 Linux sensor → 一次受控真实入站事件。AI 做传感器接线和展示；你练“事件来源与状态不能混推”的判断及一个映射/计数测试。没有 Linux 观测环境就清楚停在 fixture，不能显示成 live。

### D：让自己的内容真正留下来

World 方向在 C 验收后进入；Radar 方向先补可解释指标和小规模性能记录，再决定是否进入 World。

AI 先核对你的博客仓库和已有文章结构，优先只读导入元数据/Markdown 并保留原链接，不要求你重写一个博客系统。还未提供仓库地址时，继续可独立完成的本地阅读体验，导入工作等真实仓库信息。

开放房屋创建/编辑之前，落实稳定作者身份、服务端所有权验证、持久存储与版本冲突处理；临时 Session ID 不能当持久作者身份。文章主题先做有限配置，不执行作者任意脚本。

你只练一个权限或版本冲突用例：访客不能修改别人的房子，或旧版本保存不能覆盖新版本。验收包含刷新/服务重启后内容仍在、跨设备可读、未授权修改被拒绝。写回 GitHub 是另一个需明确授权的功能，不混入只读导入。

## 6. 兴趣研究怎样安排

插值研究保留为支线：时间映射、自适应缓冲、批量轨迹样本都值得实验，但不再作为 A/B 的必修前置。出现实际抖动回归时按故障修复处理。

每次只比较一个变量，先记录基线、真实路径误差/停止误差/延迟和运行条件。当前切线冻结不等于全局速度连续，转折归零也不是所有输入下无过冲的数学证明；没有覆盖就不作保证。

近乎无限的世界、AOI、二进制、WebGPU、eBPF 和大规模压测继续保留，等固定街区体验成立或有瓶颈证据再做。不要用这些专题阻塞一个可分享的最小版本。

## 7. 判断新方式是否有效

连续完成两个功能包后看三件事：是否有新增可演示行为；是否花太多时间等待或复制机械代码；你能否不看解释完成一个小改动并说出失败边界。这两个包里至少亲手改过一次核心行为，不能一直只运行 AI 写好的测试；可以查语法，不直接复制目标实现。

功能快但不能改，就在下一包补一个针对性练习；练习很多却没有新体验，就减少重复手写、扩大 AI 的实现范围。已会的内容用一次短检查跳过，不要求默写整个功能。未练到的能力写“未测”，不据此给自己贴能力弱的标签。

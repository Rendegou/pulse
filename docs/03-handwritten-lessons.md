# PULSE 手写课程卡

每次只执行一张卡。除 L1 的源码定位外，后续拟定函数和文件都是练习目标，不代表已有实现。先看题目，再按需要展开提示；不用一次完成所有子任务。

## L0 画出一次真实调用链

**练习：** 20 分钟；先不改代码。打开 `main.go`、`static/index.html`、`static/app.js`。

**你要交付：** 在笔记里写出“浏览器 A 移动鼠标 → 浏览器 B 画点”的完整箭头链，并在每个函数旁标上调用者：浏览器、Go HTTP 库、自己的代码或 goroutine。

**验收：** 能回答 `ServeHTTP` 为何被调用、readPump 为什么知道当前 Session、入队为什么还不等于发出、draw 为什么会再运行。

**迁移：** 把起点换成“浏览器 B 关闭”，画出 leave 的产生和消散。

<details><summary>提示 1</summary>

从 `addEventListener`、50ms interval、`ReadMessage`、`Broadcast`、`WriteMessage`、`ws.onmessage`、`requestAnimationFrame` 找跨边界的箭头。不要只列函数名字。

</details>

## L1 接通插值绘制

**为什么先做：** 你已经写了缓冲与调用，这一步能直接验证你是否理解“计算结果必须被下游消费”。

**范围：** `static/app.js` 的 `draw()`，随后清理已完成接线的两处 TODO 和过时文件头。暂不修改 Go 协议、重连或 buffer 算法。

**写之前：** 口述 `s`、`p`、`x/y` 分别是保存的状态、选中的绘制位置、还是画布像素。手算远程 p=(0.25,0.75)，画布 800×400 时应画在哪里。

**你要写：** 自己的点用即时位置，远程点用插值返回值；确保选择位置发生在坐标换算之前，后续点和光环使用同一坐标。

**验收：**

- `node --check static/app.js` 通过。
- 重启 `go run .` 后打开两页；A 移动时，B 看见远程点移动；反向再测一次。
- 停止移动后停在最后收到的位置，不外推、不返回出生位置。
- 自己的点仍随鼠标立即响应，不增加 120ms 本地延迟。
- 断点看到 `ctx.arc` 参数来自选中的位置；不能只报告“p 算对了”。

**迁移：** 临时比较 RENDER_DELAY 为 0 与 120 的表现，记录差别后恢复。效果取决于网络和帧率；没有明显变化也要记录观察，不能预设必然丝滑。

<details><summary>提示 1：先找结果的消费者</summary>

检查计算 `p` 前是否已经计算了 `x/y`，以及后面的 `ctx.arc` 究竟接收哪个变量。

</details>

<details><summary>提示 2：只给顺序</summary>

先选 position，再把 position 乘画布尺寸，最后画。变量声明也要按这个顺序。不要把网络采样频率提高当成修复。

</details>

## L2 手算并独立实现插值

**入口：** 当前 `samplePosition`。保留原函数；在 `work/` 的本地练习文件先写，再决定是否替换主程序。

**本课分两次：** L2a 写一个只接收 a、b、k 的数值插值纯函数；L2b 写“在有序样本中选择两点”的采样函数。导出测试函数时再迁到 `static/interpolation.mjs`，并核对 HTML 的 module 加载。

**契约：** 输入坐标为有限数；队列按接收时间升序；采样不修改输入。空、单点、早于第一点、晚于最后点、两点之间都必须有确定结果。

**先手算的测试：**

- `(a,b,k)=(2,10,0.25)` 得 4。
- A=(1000,0.2,0.4)、B=(1050,0.8,0.6)，时刻 1025 得 (0.5,0.5)。
- 时刻 990 取 A，1060 取 B；空队列返回传入的 fallback。
- 时间相同的连续样本保留后到的一个，或显式取后者；不允许除零。这个去重策略在入队函数中固定，并单独测试。

**验收：** 用 Node 内置 `node:test` 给纯函数写行为测试；浮点计算采用合理误差比较；不把 DOM、WebSocket 或真实计时器塞进测试。

**迁移：** 关闭原实现，独立写一个透明度插值例子，解释它与位置插值有哪些共同部分。

## L3 有界采样与缓冲

**入口：** mousemove listener、50ms interval、`onMessage` 的 cursor 分支。

**L3a：** 写 `normalizePointer(clientX,clientY,rect)` 纯函数。明确零宽高返回无效结果，边缘位置夹紧在 0..1。事件处理器负责读取 DOM，再调用函数。

**L3b：** 写 `appendPositionSample`，每个远端保留最近 1 秒且最多 32 条。用传入的 now 而非函数内部读时钟，处理相同 timestamp；必要时保留 last-known position 供空缓冲 fallback。

**L3c：** 发送前检查连接 open、dirty 和 bufferedAmount；忙时只留最新 pending，不继续堆过时坐标。重连 welcome 后明确清掉旧连接 pending 并重新绑定自己的身份。

**验收：** 输入 1000 个样本后长度不超过 32；停止后位置保留；连接未 open 不调用 send；连续移动只维持一个发送 interval。每个子题分别验证。

**迁移：** 用键盘箭头更新 pending，不更改 cursor 协议。此题用于检验输入源与发送层是否真正分开。

## L4 自己完成点击脉冲

**先学：** 状态可以被新值覆盖，点击是一次发生过的事件；两者不能照搬同一套重发规则。

**L4a 协议：** 按 [方案的消息契约](01-project-plan.md#5-最小协议先保持现有-cursor-命名) 写请求与响应样本，说明 eventId、clientEventId、Session ID 的区别。先在服务端写解析校验测试。

**L4b 服务端：** 解析一条 pulse，身份从当前 Session 取；坐标与事件标识校验后广播。给每连接 2Hz、突发 4 的小预算，不让客户端决定无限扩散数量。

**L4c 前端：** click 只发送；收到服务端接受的 pulse 才创建视觉对象。用独立的 bornAt 和 600ms 生命周期画扩散圆；到期删除；最多 64 个活动效果，去重缓存也有时间和数量上限。

**验收：** A 点击一次，A/B 各播放一次；不把 pulse 当持久坐标；坏坐标被拒绝；重连不会重放之前点击；每个效果只存在约定时长。

**迁移：** 设计一种“滚动时轻微发光”的效果，先判断它应该是状态还是离散事件，只写契约不用实现。

## L5 Go 的值、指针、锁和快照

**入口：** Session、Hub.Snapshot、readPump、writePump。

**L5a：** 给快照返回类型设计仅包含 ID/X/Y/Join 的 `SessionView`。先写测试：取出快照后修改 Hub 中的坐标，旧快照不变，公开 JSON 不出现 channel 等运行字段。

**L5b：** 把“更新当前 Session 坐标并构造广播值”收进明确的 Hub 方法；说明谁持锁、返回值可否在锁外使用。不要从浏览器 ID 查任意 Session。

**L5c：** 画出多个 goroutine 同时读写的字段与锁。给入队/删除/close 写一份顺序图，避免拆函数时破坏原来的同步关系。

**验收：** 行为测试通过；并发路径在支持的环境用 race detector 检查；注释写明锁由谁取得。没有测试实际触达的路径不能宣称并发安全。

**迁移：** 给 Session 加一个假想的 slice 字段，只解释快照为什么需要额外复制，不实际扩展功能。

## L6 连接可靠性：每次只处理一条失败路径

本课不是一个提交，拆成以下四题。

**L6a 输入：** 加消息读取上限、消息类型白名单和必填字段验证。Go 的 float64 零值无法区别“没传 x”与“传 x=0”，解析结构需要保留字段存在信息。测试缺 x/null/越界/超长/未知类型。

**L6b 退出：** 写失败时关闭 conn，唤醒 reader；一个 owner 负责注销、close(send)、leave，且只发生一次。welcome 写失败也必须走清理。测试 writer 失败后在线数最终下降。

**L6c 心跳与重连：** 设置 ping/pong、读写超时；frontend 回调只处理当前 socket generation，旧 onclose 不得清空新连接；最多一个重连定时器。重试带上限与抖动，页面销毁时释放。

**L6d 慢连接：** 队列满按初版策略断开慢消费者，重连后用 welcome 快照恢复。测试其他连接仍能接收消息，无 send-on-closed-channel、无重复 leave。未来再学 cursor coalesce。

**验收：** 每题有一种可重复的故障注入；连接名额和 goroutine 能回收；测试只跑自己的本地服务。先讲清 owner，再写 defer/close/sync.Once。

**迁移：** 解释“TCP 看似没断但对端不再读”为什么和“关闭浏览器”是不同用例。

## L7 Idle / Focus 和真实指标

**L7a：** 写纯状态判断函数，输入 now、lastActivity、focused，约定 30 秒无活动进入 idle。读不到 cursor 不等于断线，后台页面不等于离线。服务端用一个共享 ticker 扫描，不给每个连接新增独立活动 timer。

**L7b：** 新增每秒 accepted cursor 数。先累计计数，再用两次快照差值除实际间隔；区分 received、accepted、fanout、dropped，别把它们都叫 events/s。

**L7c：** 校准 heap/sys 的 MiB 单位；若需要 RSS 单独增加 Linux 采集来源。加入应用级 echo 后，用同一客户端时钟测 RTT；不要把两台机器的时间直接相减算单向延迟。

**验收：** 用虚拟 now 测 29/30/31 秒边界；切页只改变 focus；速率窗口变化时计算正确；没采集到的指标显示 unavailable。

**迁移：** 用一段包含 10 个 RTT 样本的数组手算中位数，再解释小样本 P99 的局限。

## L8 小规模负载和一次有证据的优化

**任务拆分：** 先写连两条 WS 的 Go 测试客户端；再参数化为 10/50 条；再分别加入空闲、20Hz cursor、慢消费者三种场景。不要一开始跑 10K。

**先预测：** 50 条连接每条 20Hz 当前全量广播约 50,000 次投递/秒；这不是 50,000 个用户事件。假定每次投递 100 字节，单纯 payload 约 5 MB/s，另有协议/TLS/系统成本。

**记录：** 代码版本、机器、客户端位置、连接数、活跃比例、输入率、投递率、消息字节数、运行时长、内存、CPU、RTT 样本口径和错误。

**验收：** 能重复一组结果，定位一个瓶颈，单独修改一个因素，再对比同配置数据。只有图更密、没有真实 socket 数证据不算压测。

**迁移：** 解释 1000 个空闲连接和 100 个高频全量广播连接哪个更重，为什么不能只凭连接数判断。

## L9 理解一次发布

**入口：** `.github/workflows/deploy.yml`、`deploy/Caddyfile`、`deploy/caddy.service`。

**任务：** 画出 push → vet → 构建 → 上传 → 远端安装脚本 → 服务重启 → 浏览器获取内嵌静态资源的过程。标记哪些文件当前不在仓库。

**下一小步：** 在独立测试流程中加入 `go test ./...` 与 JS 测试（文件建立后），再给部署写版本检查与失败回滚契约。原工作流执行 vet 和 build 不代表测试已覆盖行为。

**验收：** 能说明为什么仅刷新不能加载未重新编译的嵌入式 app.js，为什么 Caddy 活着不代表 pulse 活着，为什么提交与推送不是一回事。

**迁移：** 只在本地模拟“新二进制启动失败”，写应保留哪些旧文件和如何确认恢复。公网演练另按明确任务执行。

## L10 Host Radar：回到最初的产品目标

先通过 L6 的边界与生命周期，再分三步连接真实主机事件；可以与 L8/L9 的进度协商，不必等全部性能专题完成。

**L10a 事件到画面：** 用显式 `fixture` 模式手写一个 `host_event → port节点 → 有界效果` 的小链。保留来源标签，不接真实抓包。只复用原型的视觉语法，不复制随机指标。

**L10b 传感器到 Gateway：** 在自己的 Linux 测试主机上，独立 sensor 通过有界本地 IPC 输出白名单元数据。Gateway 普通用户运行；检查 schema、来源、速率、断线和过期。不要抓取或保存 payload。

**L10c 一个受控 SYN：** 从自己另一台机器向指定测试端口发起一次连接；先证明报文到达主机捕获点，再证明 sensor → Gateway → 浏览器。云侧安全组提前丢弃的流量不能要求主机 sensor 看见。

**验收：** 画面与一次受控真实事件对应，live/fixture 明确；未观测到握手不能写 ESTABLISHED；没有事件与 sensor 离线显示不同。详细契约见 [原型到产品](06-prototype-to-product.md)。

**迁移：** 只画设计：如果之后有每秒 10,000 个主机事件，怎样通过端口聚合减少传给浏览器的数据量？不要先加 eBPF。

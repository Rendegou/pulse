# PULSE 代码、注释与交付规范

规范的目的：让你读得出状态属于谁、函数做出什么承诺、错误如何返回，以及怎样验证结果。一个统一的注释 Skill 约束所有方法，不是每个方法单独建立一个 Skill。

## 1. 当前目录与所有权

以 [16 前后端地基](16-frontend-foundation.md) 为准。前端 Vue 3 + Vite，源码唯一入口 frontend/src；后端同一 package main 按职责拆分。static/dist 是构建输出，禁止手改。

## 2. 按真实职责拆分

组件负责界面，runtime 装配协议，watering 管动作，connection 管连接，engine 管高频场景。不要在 Vue 响应式对象里塞粒子或 WebSocket，不在模块顶层启动无清理的定时器。

只有实际接口或测试需要才继续拆目录，不预建 Router/Pinia/服务层，不因用户尚未学习而阻塞必要实现。

## 3. 函数的最低契约

写函数体前先写出：

- 谁调用它、何时调用。
- 输入来自可信内部状态还是外部消息；单位是什么。
- 返回值表示什么；空、缺字段、越界、失败怎么办。
- 是否修改参数/共享状态，是否读 DOM、网络、时钟或随机源。
- 是否拥有资源；谁负责关闭、移除或停止。

纯计算尽量显式接收 `now`、队列和尺寸；事件处理器负责从环境中取值，再调用纯函数。不要给一个小练习制造多个抽象接口。

## 4. 中文注释标准

完整执行规则见 [comment-convention](../.agents/skills/comment-convention/SKILL.md)。每个函数、方法、Handler 和业务回调都有中文注释，写在声明或回调注册附近，说明用途与非显然契约。

Go 注释从函数名开头。例如计划中的方法声明：

```go
// Snapshot 返回此刻的公开在线信息，供新连接建立一致的初始视图。
// 在读锁内复制公开字段；返回值不共享可变坐标，也不携带发送通道。
func (h *Hub) Snapshot() []SessionView
```

上例是签名示意，不是完整 Go 文件；SessionView 已在本轮 hub.go 中实现，具体合同以源码为准。

JS 示例只展示声明契约：

```js
// normalizePointer 将视口鼠标位置变成与画布尺寸无关的 0..1 坐标。
// rect 宽高非正时返回 null；不读 DOM，不改传入对象。
// 当前实现见 static/pure.js。
```

不要写“遍历数组”“设置 x”“返回结果”这类复述。位运算、队列取舍、时序假设、单位换算值得写内联注释。

当前历史实现的过时注释和未说明的回调逐课修正，不把这次文档更新称作全部代码已达标。`docs/references/` 中的原型与概念原件作为历史材料原样保留；从原型迁入正式代码的新函数需遵守本规范。

匿名回调同样需要说明行为。事件注册上方的注释可以覆盖其回调；多个分支有不同副作用时分别说明，不机械地给每个表达式加噪声。文件头不能替代函数契约。

## 5. Go 数据所有权

- Session 属于一条连接；浏览器提交的 ID 不决定服务端修改哪个 Session。
- Hub 集合与共享 Session 字段的保护规则集中说明；不要同一字段一处加锁、另一处裸写。
- 公开消息优先使用值 DTO；增加引用字段时重新检查快照复制。
- 不持 Hub 锁执行阻塞网络 IO；非阻塞入队与注销的同步要整体设计。
- 一个连接明确普通 reader/writer 与清理 owner；关闭 channel 的责任只给一处。
- 失败处理写出结果：拒绝、丢弃计数、断开、重试或返回错误。不要新增无说明的 `_ =`。
- 随机身份下一阶段改为足够空间的 ID（例如 16 字节），并在登记处处理冲突；当前 2 字节后缀只是旧骨架约束。

## 6. JavaScript 状态与绘制

- 网络回调负责校验消息并更新状态；draw 读取选定位置、执行绘制和明确的视觉过期处理，不发业务消息。
- 本地输入状态、远端历史样本、渲染位置和 CSS 像素不要复用一个模糊变量。
- 每个计时器、listener 和连接写清创建/销毁位置；重连不重复启动发送器或绘制循环。
- 后台标签页可能被降低计时与绘制频率，不以“每次一定间隔 50ms”作为算法前提。
- 所有队列同时考虑时间和条数边界；循环里不要无界创建对象或拼日志。
- 真实事件的文本进入 DOM 用 `textContent` 或明确的元素构造，不把服务器数据拼进原型的 `innerHTML`。
- 一项 canvas 变更要确认真实使用它的坐标与样式，不能只验中间函数。

## 7. 命名与错误

- Go 依照现有 CamelCase，JavaScript 函数用 camelCase；常量带语义，时间变量标单位，例如 `renderDelayMs`。
- `cursor`、`pulse` 等消息名称以双方共同契约为准；新增类型同时补解析和未知类型处理。
- 避免含糊的 `data2`、`tmp1`、`handleAll`；短循环索引不需要过长名字。
- TODO 只写真实未完成事项并关联课程，例如 `TODO(L6b): writer 失败后联动关闭 reader`。完成后删除，不能把已实现动作继续标成待办。
- 类型校验与业务校验分开：JSON 能解析不代表字段齐全、坐标有效或频率允许。

## 8. 一次功能包的完成定义

1. 改动对应一个可描述的行为，保留用户已有实现。
2. 注释与真实代码一致；说明非正常输入和资源生命周期。
3. 有匹配风险的验证：纯函数做单元检查，跨页面行为做整条链验证。
4. `gofmt` / vet / JS 语法等与改动相关检查通过。
5. 分别记录 AI/用户完成的部分与仍需帮助的关键点；没有学习证据就记未测，不要求重写整个功能。
6. 产品验收与用户关键练习分开记录；学习未完成不阻止不依赖它的实现，产品行为未验证不能记为交付完成。

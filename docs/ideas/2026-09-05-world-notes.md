# PULSE World Notes：把博客放进一个可以相遇的世界

> 2026-09-05 的想法纪念。状态：未来构想与交互原型；不改变当前 PULSE 手写课程和发布范围。

## 我们想保留的感觉

个人博客不一定是一份按时间排列的文章列表。它也可以是二维世界里的一间小房子：有人在窗边写文章，有人偶然路过，有人把自己的房子搭在旁边。你看得到别人的指针，知道这一刻有人和你一起看着同一片地方。

这个想法来自你正在做的 PULSE，以及你希望把自己 GitHub 上的博客项目与实时互动结合起来的念头。这里没有分析或接入那个博客仓库；具体仓库结构和发布方式留待真正推进时再核对。

**一句话：一串地址找到一个地方，一间房子承载一个人的表达，实时指针让阅读变成一次相遇。**

## 世界里的几件事

### 地址就是约定见面的地方

输入“夜航”“雨巷”或者任何一串有意义的文字，前往对应街区。朋友输入同样的地址，就能找到同一个地方。分享的是位置和房子，而不只是某篇文章的网址。

正式版本需要决定：字符串代表独立房间，还是同一连续世界中的一块区域。本构想优先保留“同一个大世界、命名区域”的方向；Demo 用彼此独立的本地街区来表达跳转感，不声称已经实现跨街区连续加载。

地址规范先约定：去掉首尾空白、Unicode NFC、保留大小写。正式版由服务端保存地址与区域的映射并处理冲突；不能把短哈希直接当唯一身份。公开地址也不是权限密码。

### 房子是一个人可以搭建的博客空间

你选择空地，给房子命名，挑外形、颜色、文章样式，把内容放进去。第一版不必做自由建模：先用书屋、工作室、庭院几个组合，让人能表达“这像我”。

以后可逐步拥有多个房间：文章墙、相册、书架、项目桌、留言簿。每种组件都有明确的数据结构。先允许主题、字体、布局和有限组件编辑，不直接执行陌生作者的脚本。

“房子”是视觉和空间入口，文章仍需要正常的网址、标题、可选择文字和可键盘阅读的页面。世界坐标改变时，文章身份与永久链接不应一起失效。

### 房子外面有实时的人

最值得保留的 PULSE 能力是 Presence：低频采样后的指针、自己的即时反馈、远端插值、进入与离开、轻量点击脉冲。有人在附近读文章，比一个冰冷的在线人数更容易让人感到相遇。

但指针只说明当前交互状态，不自动等于实名身份。允许隐藏指针、安静阅读，尊重作者空间的访问范围。阅读内容不要因为开启 Presence 就默认保存完整行为轨迹。

### 漫游不是永远加载所有内容

画布可以平移缩放，远处保留稀疏街区和建筑轮廓，靠近后再加载房屋详情和文章。产品感觉可以近乎无限；计算、内存、坐标、网络订阅和可见对象始终有上限。

未来按区域切块，只订阅当前视野及附近区域。超远处不广播每个人的指针，改为聚合或不显示；为相机大坐标采用局部原点等策略时再做专项设计。第一天不实现 MMO 架构。

## 这次的 HTML Demo

[打开独立原型](../../outputs/pulse-world-demo.html)。单文件 HTML，不依赖 npm、图片 CDN 或 Go 服务；可以直接打开。

已经表达的体验：

- 深色 PULSE 网格、青色指针、绿色个人空间标记。
- 输入字符串切换街区；地址也保存在 URL 的 hash 里。
- 拖动画布、滚轮/按钮缩放、方向键漫游、回到中心。
- 点击示例房子读文章，或用“附近文章”按钮逐间访问。
- 搭建一间自己的房子：选择三种外形、三种文章主题、填写名字、署名、标题和正文。
- 在空地选址；房子不能明显重叠；保存后可以回家编辑。
- 每个街区的一间自建房存在当前浏览器 localStorage，刷新后恢复；存储不可用时提示仅保留当前页面。
- 两个明确标注的演示邻居指针，可关闭；不是远程用户或真实 WebSocket。

原型限制：每街区四间示例房和一间自建房；一间房只有一篇纯文本文章；没有账号、远端存储、跨设备分享、实时多人或博客仓库同步。缩放和相机坐标有边界，移动到远处只会看到网格，不会不断生成真实内容。不同浏览器对直接打开本地 HTML 的存储可能有差异，可用本地静态服务器获得稳定 origin。

地址相同表示同一套确定性示意布局，不表示朋友能看见你的本机房子。真正共享需要服务端内容与权限契约。

## 和当前项目怎样衔接

这份想法不要求现在停止学习去做一个新平台。当前课程仍有用：插值让指针自然，点击脉冲是打招呼，连接生命周期和背压支撑多人共处。把这些学扎实，未来可以把画布的光点背景换成房屋世界。

如果未来决定推进，按下面的最小顺序：

1. 先做一个固定街区、两间房、每房一篇真实文章，文章保持可直接访问的链接。
2. 接入现有 PULSE 两个真实客户端的指针，让人能一起逛。
3. 让一个明确的作者身份创建和编辑自己的房子，服务端验证所有权，保存冲突采用版本检查。
4. 再核对你现有 GitHub 博客：优先只读导入 Markdown/文章元数据，保留原链接。仓库 token 只在可信服务端，Demo 不读取凭据。
5. 最后加入区域加载与邻近订阅，再考虑自由装修、留言、关注或社区机制。

只读导入与写回 GitHub 是两个不同阶段；空间装饰数据和文章内容最好分别保存，避免移动一间房就必须修改文章仓库。

## 有意思，也需要验证的地方

这个方向的价值在于空间记忆和同时在线感：人可能记住“拐角那间暖白色书屋”，而不只是某个用户名。它也有真实成本：想快速找文章的人可能不想拖动地图，人数少时世界容易显得空，任意建房与编辑又会引入占地、权限和内容管理问题。

因此保留两条路：可以慢慢逛，也可以搜索文章、打开作者页、直接读链接。空间是新的入口，不应成为阅读必须跨过的障碍。陌生人到访、留言或改造需要可控，而不是默认允许破坏别人的空间。

未来第一次体验验证只问三件事：

- 朋友能否在一分钟内找到你的房子并读到一段内容？
- 两人是否会自然利用指针或脉冲表达“我在这里”？
- 你是否真的愿意在自己的房子里更新第二篇文章？

如果这三件事有感觉，再讨论“无限”；如果暂时没有，原型仍然完整保留了今天这个念头。

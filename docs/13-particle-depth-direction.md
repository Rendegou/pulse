# PULSE：先让靠近产生纵深

2026-09-08。依据用户提供的 DeepSeek 会话导出、当前源码及已有截图重新收敛方向。本文是下一轮建议与执行边界，**不是新效果已实现或用户已确认满意的报告**。

## 1. 这次真正要解决什么

用户在记录末尾明确反馈：“太丑了，不用这个复杂，做点粒子效果有点 3D 空间感就行啊。”此前反复强调放大、缩小时要有层次感。

稳定的目标是：俯瞰一个可探索的巨大空间；以点和少量线形成个人区域；靠近时能感觉到穿过不同深度；内容与其他人的存在自然浮现。房屋、岛、书页都是曾经尝试过的载体，不是必须保留的实体模型。

建议继续采用“文章岛”作为产品称呼，视觉上表达为**有起伏、有厚度、边缘逐渐稀疏的粒子地表**。不要求画出海岸、岩壁或悬空石块。

## 2. 前几轮为什么没有解决

- **把深度诉求变成了物件选择。** 房屋、纸碑、灯笼不断替换，又加入松树、瀑布和月亮；镜头与空间的核心体验迟迟没有单独成立。
- **探索方式反复改变。** 俯瞰、第一人称、环绕、横版是不同的交互结构。换一个视角后，之前的拖动和靠近预期也被换掉了。
- **当前产品的高度效果不足。** `static/world.js` 的 `project()` 中，高度只进入屏幕 Y 偏移；返回的 `scale` 不依赖高度。它能制造叠放，却不能充分表达镜头经过不同深度时的相对放大差异。
- **构图失去重点。** 现有横版截图中，台阶和大光晕占据主要面积，文章小而难读；产品文章岛截图中，三张大卡片遮挡内容，粒子背景没有参与内容层次。
- **验证回答了错误的问题。** 视差比例、平均亮度、暖色像素可以检查某些绘制逻辑，不能证明好看，更不能证明下降过程符合用户预期。记录中 v4 验证通过后，用户仍明确拒绝了它。

这也适用于此前 Codex 交付的叠页方案：交互通过不代表视觉问题已经解决。

## 3. 建议的连续体验

### 远处：先感到世界很大

画面以留白为主。几片疏密不同的粒子区域轻微隆起，同一地表延伸出屏幕。地形保持稳定，仅极少量游离粒子缓慢移动。避免均匀铺满的星空噪点，也避免画出完整球体边缘。

远处只出现个人空间名称或少数定位点，不排文章正文。用户拖动时移动世界坐标，方向保持一致。

### 靠近：深度必须由运动显现

滚轮推进的是镜头距离。极少量前景粒子先扩大并离开视野；内容所在的中层随后展开；更远的地表变化较慢。三个层次由共同的空间坐标和镜头投影产生，不能只是三个跟随屏幕的装饰背景。

保持俯瞰，必要时只加入轻微、连续的倾角变化。整段运动可以随时停下、反向或被拖动接管。到达某个倍率时，不突然切入横版或第一人称。

目标区域始终可追踪，不能为了显示特效而把它移出画面。进出路径应连续；反向缩小时，不先播放一段不可打断的返回动画。

### 近处：内容清楚，空间安静

建议先让三篇示例文章落在粒子地表的不同高度处，以小型标题标记呈现。选中一篇后显示一张清楚的预览；完整阅读沿用 DOM 阅读页。文章数量、标题和打开目标保持真实对应。

先验证此种轻量入口。书本、可拖动收藏、个性化布置仍是后续愿景，不在本轮重新决定它们的全部造型。

实时指针位于可理解的空间层上，明暗、中文/英文、简小状态区沿用。粒子不能盖住标题，也不能让真实指针混入装饰点中。

## 4. 画面收敛规则

- 只保留一个主要形态：有高度变化的粒子面。疏密和轮廓负责造型，避免靠叠加光晕来制造精致感。
- 近点更清晰，远点更淡；少量前景点负责视差，主体粒子负责区域轮廓。远景不能比文章更醒目。
- 初始调试使用单色粒子和现有背景色。先让静态轮廓与动态深度成立，再调整明暗两套颜色。
- 先关闭自动呼吸、整岛旋转、随机闪烁。静止时保持稳定，用户移动镜头时才呈现主要动势。
- 近景标签允许避让，但同一篇文章的世界位置保持稳定；不能缩放一次就重新随机排版。

## 5. 下一轮只做一个可验收改动

在正式前端接入一条“远处 → 靠近 → 停下 → 返回”的粒子深度路径，使用一块个人区域和现有三篇示例文章。可在原页面保留内部对照开关用于比较，不再创建一套独立 Demo 和另一组状态机。

第一步先验证镜头：单色粒子、固定地形、不加文章装饰。看连续操作是否出现明显的近远差异。这里不成立，就继续修镜头与空间分布。

第二步再整理构图：控制粒子密度、留白、前景数量和地表起伏，补回文章入口。只对这个方向做一轮精修，不同时推出三种新隐喻。

第三步完成产品接线：主题、双语、阅读、真实指针坐标与命中保持一致。用户评价的主要对象是一段可操作的连续体验，不是孤立截图。

## 6. 实现约束与性能边界

世界中的平面位置与视觉高度分开存储。引入高度投影时，必须一起处理屏幕命中、鼠标锚定缩放和指针地面定位；不能只改绘制，让文章画在一处而点在另一处。

采用有界镜头距离、近裁剪与远近细节切换，避免粒子越过镜头时尺寸爆炸。世界按可见区域生成，并维持确定性坐标；“无限感”不意味着无限对象、无限粒子或无限数值倍率。

Canvas 2D 可以验证小规模透视点的运动关系。若确定需要持续绘制大量空间粒子，再考虑以 WebGL 点集承载世界层；阅读和普通界面仍用 DOM。选择依据是实际数量、目标设备耗时和维护成本，不把换引擎当作美观的保证。

透视相机参考：[Three.js PerspectiveCamera 官方文档](https://threejs.org/docs/pages/PerspectiveCamera.html)。点阵空间的技术参考：[Three.js 粒子波浪示例](https://threejs.org/examples/webgl_points_waves.html)。只借鉴空间表达，不照搬示例配色、自动波浪或相机控制。

性能记录要区分生成、绘制和整帧间隔；覆盖连续拖动、缩放、静止、窄屏与减少动态。粒子密度按可见细节控制；避免每帧重新随机生成、逐点大范围模糊和不必要的全量排序。未做真实手机检查，就记录未验证。

## 7. 如何判断这次是否有进展

视觉检查由 agent 实际查看画面与连续操作，并由用户评价是否接近心中感受：

1. 暂时隐藏文章，只看粒子；靠近时依然能清楚感到前后层次。
2. 中途停住，画面稳定，空间轮廓依然能读懂。
3. 连续放大再缩小，同一位置可追踪，没有场景硬切或控制方式突变。
4. 显示文章后，标题比装饰清楚；三篇文章都能正确打开。
5. 真实指针位置与所指内容一致；不能拿模拟访客当多人验收。

语法、命中、坐标回归和性能数据负责证明程序行为。截图亮度或某个视差系数不再作为审美通过条件。

### 9.1 增补：用户批准后的“最小三维化”（同日，仅 world.js 绘制层）

用户选择“按最小改造动手”：不改协议、不改 app.js 流程、不新建 Demo，只改 `static/world.js` 绘制层三件事（后续复现时可对照本节）：

1. **z 纳入尺度**：新增 `pageFactor()`——纸页按 `z×zoom` 产生“近大远小”（有上界，杜绝爆炸）；`pageCorners()` 对投影四边形绕中心乘该系数。下降时顶层纸页(z=22)比低层(z=7/10)长得快，纵深由运动显现。
2. **纸叠厚度**：`drawHouse()` 把原来的单层偏移背面改为沿光照方向错位、逐层变暗的三层纸叠（dz −0.9/−1.8），纸页从“贴纸”变成有厚度的纸叠。
3. **纸页下有地形**：新增 `groundRaise()` 在 3 座示例命名房屋周围生成小丘（r≈70、顶高 8）；`drawTerrainLevel` 的表地粒子与小丘共用同一“高度→屏幕Y”约定抬升，纸页/弧线/选中点都加 `groundRaise` 落在地形上——岛由地形承载。

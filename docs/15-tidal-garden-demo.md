## 这次先试什么

保留用户认可的潮汐群岛氛围：自己的岛更独立，靠近海面时能看见波峰和细浪。互动先用真实鼠标指针，允许朋友和陌生人来访；未来再决定密码、权限和角色形态。

用户没有确定第一个共同活动，因此本轮选“浇水”做可玩的实验。目的在于验证：我做了一个动作，你看到了；你也回应，空间留下共同变化。浇水是否值得成为长期玩法，仍需用户试玩判断。

## 试玩入口与启动

- [单文件 HTML](../outputs/pulse-tidal-garden.html)：直接双击可单人玩，无外部资源依赖。生长记录尝试保存在浏览器本地；无法保存会提示。
- 真实双窗口：在仓库根目录使用 PowerShell 7 运行 `node work/serve-garden-demo.mjs`，打开终端输出的地址。端口由系统分配，后续启动可能不同。
- 点“打开访客窗口”，把两个窗口并排。每个窗口是一条真实连接，能看见对方指针并照料同一株植物。
- 服务只监听 `127.0.0.1`，链接仅供本机试玩，不能发送给外地朋友当作线上邀请。
- [原始潮汐 HTML](../outputs/pulse-tidal-islands.html) 保留原样。当前正式站点和 Go 服务没有被本轮修改。

## 三分钟体验

1. 进入时，自己的岛是主体，周围留出海面。
2. 点击“靠近这株植物”，镜头连续靠近。也可拖动、滚轮、双指或用缩放按钮探索。
3. 近处按钮变成“浇一点水”，植物本身也是同一动作的入口。
4. 水落下，叶片舒展；第二次出现花苞，第三次开花。每次之间留短暂间隔，让回应可被看清。
5. 打开另一个窗口，两边移动鼠标并分别浇水。两个不同连接在六秒内照料同一株植物，会出现额外的共同光点与提示。
6. 重新打开页面，植物保留状态。切换另外两座示例岛，各自有独立植物。

不开成长任务列表，不要求每日签到，不枯萎。一个人也能开花；多人带来的是相遇感，不是数值门槛。第三次之后仍可浇水，动作有回应、最近照料记录会更新，生长阶段停在开花。

## 游戏参考如何转化为自己的规则

[《动物森友会》官方拜访介绍](https://animalcrossing.nintendo.com/new-horizons/share/)强调向朋友展示自己的岛、一起游玩。本 Demo 借用“来到一个地方再发生互动”的顺序；没有照搬游戏的种植概率或奖励系统。

[《光·遇》官方共同空间与共同回忆说明](https://thatgamecompany.helpshift.com/hc/en/17-sky-children-of-the-light/faq/521-what-are-message-shrines-message-candles-message-boats-shared-spaces-and-shared-memories/)介绍了用物件布置共同空间、留下可被别人发现的回忆。本 Demo 从中提炼“一个小动作也能表达存在”的方向；六秒共同浇水、三次开花等规则均为本轮原创实验，没有复制其素材、货币或运营规则。

## UI 与画面变化

- 邻岛中心从约千单位拉开到约三千单位；日常视角不显示远处邻岛，拉远或点导航才能发现与拜访。靠近时不把所有岛挤在同一屏。
- 水面用主涌浪、交错波与近景细浪叠加高度；浪尖明暗取自主波相位，细节随靠近渐显。继续沿用 GPU 粒子与独立地形缓存，没有通过不断添加粒子制造层次。
- 植物采用与岛屿相同的三维投影：细茎、折面叶片、中脉颗粒、花瓣和地面点圈。植物不是屏幕上贴着不动的图标。
- 远处先出现靠近入口，近处才出现浇水语义；画布与按钮共用动作函数。拖动不会触发照料。
- 来客保持鼠标指针和简短编号；数量来自实际连接。编号表示当前连接，不是注册用户或永久身份。
- 明暗与语言沿用原稿设置，默认系统明暗、中文；此分支使用独立存储键。手机保留同一主动作；系统减少动态设置下反馈改成静态变化。

## 数据边界与实现入口

前端编辑入口为 `work/garden-interaction.js`、`work/garden-demo.css` 和 `work/build-garden-demo.mjs`。运行 `node work/build-garden-demo.mjs` 生成独立 HTML；不要同时手改生成文件与源文件。

`work/serve-garden-demo.mjs` 是独立的 Node 演示服务。浏览器用 SSE 收取状态，用 HTTP POST 发送指针和浇水。选择这套实现是为了不安装额外依赖，正式产品后续应接回已有 Go / WebSocket 链路，不能把 Demo 服务当成新的产品架构。

- 植物状态由本地服务统一确认；前端收到确认后才改变生长阶段。
- 三座植物分别存储 `care` 与 `last`；版本递增，旧快照不覆盖新快照。生长阶段上限为三，最近照料记录可以继续变化。
- `eventId` 对每连接最近 64 次浇水去重；冷却约两秒。界面冷却稍长，便于看清水落下。
- 先写临时文件再替换状态文件，落盘失败不广播成功。默认数据路径为 `work/garden-play-state.json`，已加入忽略规则。
- 最多 16 个连接、4KiB 动作体、65KiB 左右的慢连接写缓冲预算；服务拒绝非预期 Host 与跨来源请求。
- 减少动态时不持续播放波浪；隐藏页面停止绘制。指针最多约每 65ms 上报一次，不重试过期坐标。

**尚未实现账号、岛屿所有权、离线访客身份、物件编辑、权限与互联网部署。** 当前所有人访问的是三个固定示例空间；“你的原点”是体验文案，不表示已创建私人岛屿。页面中的访客窗口是真实连接，但同一人打开两页仍只是一个人，不能用来证明真实社交体验成立。

## 已做验证与限制

语法：生成后的内联脚本、Node 服务通过 `node --check`。

协议集成：`node work/garden-demo.test.mjs`，九组检查通过，报告见 [协议验证](../work/garden-protocol-validation.json)。覆盖真实 SSE 加入离开、世界指针、两端一致水动作、重复去重、非法输入与冷却、共同照料、重启恢复、跨岛并发、落盘失败不更新。

浏览器：实际检查桌面与 390×844 布局；两个真实窗口分别浇水后均为阶段二、版本二；手机画面观察到另一窗口的指针；之后第三次浇水显示开花状态。检查了中英文、深浅色，修复远近按钮语义与偏好读写键不一致。最终新入口从未照料状态开始，未捕获到控制台错误。机械界面检查未报问题。

未验证：真实手机双指手势、系统减少动态的设备实测、低端 GPU 帧率、长时间多客户端压测、跨设备互联网联机和生产环境。GPU 提交耗时不能当成实际帧率；本轮不宣称已经解决所有性能问题。

## 试玩后再决定

先只判断一件事：**当另一个人的指针来到植物旁，并真的改变了它，你是否愿意停留和回应？**

如果愿意，下一包再接正式空间身份与拜访入口，让主人选择植物的位置，访客只能照料。如果仍然无趣，优先调整“共同操作的物件和反馈”，不要先投入种植经济、无限地图或更多装饰。

想顺便理解一个关键点，可以从 `waterPlant → postGarden → handleAction → persist → acceptGarden` 跟一次调用：为什么不能只在前端先加一次 `care` 就算成功？这是可选的理解入口，不阻塞试玩，也不等于本轮已经独立掌握。

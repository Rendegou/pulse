# 从最初 Demo 到真实 PULSE

> 2026-09-07 排期说明：本文件保留原始 PULSE 与 Host Radar 的专题设计；实际顺序见 [AI 协作路线](07-ai-assisted-roadmap.md)。先点击互动与可靠连接，再推荐固定博客街区；不要求先完成全部主机观测课程。

## 1. 原始愿景保留什么

根据你提供的“个人网站创意探索”对话，PULSE 的吸引力有三个来源：看到别人正在活动，看到主机正在接收什么，以及亲眼观察小机器承载大量连接时的性能。

保留 **Presence / Host Radar / System / Stress** 四个方向。教程先降低每次要处理的复杂度，再逐步恢复这个愿景；不是把项目长期收缩成一个多人鼠标页面。

- [PULSE v0.1 概念与技术设计原件](references/PULSE-concept-v0.1.original.md)。

## 2. 原型已经表达清楚的部分

- `SYSTEM / PRESENCE / HOST RADAR` 通过 mode 条件选择绘制层，可以保留这一视图关系。
- 青色访客、橙色主机事件、红色 scanner-like、灰色 synthetic，有可延续的视觉区分。
- 中央视图配合端口概览、事件流和底部指标，让用户既看到活动，也能追问来源。
- 原型已有 `LIVE · DEMO DATA` 和 `EVENTS ARE SIMULATED` 标识，这是正确的诚实起点。

不需要先推倒界面重做。让一个真实事件形成可理解、可复查的反馈，比再堆更多粒子效果更适合作为下一阶段的成果。

## 3. 还不完善的具体地方

### 3.1 原型显示的连接不是实际连接

`real` 初始值为 14；`addHuman()` 增加计数并添加随机运动粒子，没有 WebSocket 建连。生产文案应称“连接/会话”，不能仅凭 WebSocket 或 User-Agent 判定是真人。

**课程转换：** 已有 Session 消息替换原型的 addHuman；空场时说明“当前只有你”，给“打开第二个窗口”的入口。不要填随机在线人数制造热闹。

### 3.2 Stress 同时混合了三种不同概念

原型按钮将 `synthetic` 在 0/10000/50000 间切换；绘制数由 `Math.min(1800,300+synthetic/35)` 控制；并未创建对应数量的对象或网络连接。数字、视觉密度和真实负载是三回事。

**产品改进：**

- “视觉预览”只在浏览器生成示意，明确不会压服务器。
- “查看最近压测”显示带日期、环境与版本的真实结果。
- “运行压测”属于有权限的管理操作，有目标白名单、总量、时长、并发任务上限和停止按钮；不对匿名访客开放任意扩容。

L8 先交付真实小规模 loadgen，之后才能把它接到管理界面。50K/100K 仍是挑战目标，不是页面按钮能证明的容量。

### 3.3 指标来自公式，缺少口径

`updateMetrics()` 的 RSS 为 `216 + synthetic * 0.0094`，P99 含 `Math.random()`。`portRates` 只累加，却以 `/s` 显示。它们足以模拟布局，不能作为观测实现直接搬进产品。

**课程转换：** L7 给每个指标登记来源、单位、时间窗、缺数据状态。端口速率按窗口计数/实际秒数计算；没有 latency 样本就显示未采集。MEM/CONN 区分稳态增量估算与进程总内存除连接数。

### 3.4 端口事件的语义过度确定

原型把 `port===443` 直接标为 ESTABLISHED，其他多为 SYN；端口号不能证明握手成功。SYN 尝试、socket 状态、HTTP 请求和 PULSE 会话分别由不同来源观测，不能一条线自动推导出全部。

**课程转换：** Host Radar 初版只展示确实观测到的 `tcp_syn`，把捕获来源写进事件。后续有 socket state 数据才加 established/closed；scanner-like 是带理由的启发式分类，不是身份认定。

### 3.5 Host 线没有真正落在被访问端口

`drawPorts()` 画了端口节点，但 source 动画的目标固定在中心 Server；事件虽有 `port` 字段，线的终点没有使用对应端口坐标。

**课程转换：** L10a 写一个 `port → normalizedPosition` 纯函数，事件目标通过端口查表。随后增加点击端口过滤、选中事件显示来源类别/时间/端口/模式。这是很适合独立手写的小任务。

### 3.6 时间依赖帧数

`sources` 每帧增加 `.016` 的 age，访客每帧加固定速度。高刷新率和后台恢复时速度会与预期不同。

**课程转换：** 用同一页面时钟计算 elapsed，纯视觉生命周期按 `now-bornAt`；速度以单位/秒乘 dt，大暂停时明确夹紧/跳过策略。能复用 L2 的纯函数测试方法。

### 3.7 真实数据接入后的状态和容量没定义

原型中的 sources 在 host 层隐藏时不执行 age/filter，但生成 interval 继续运行；`addHuman()` 可无限加粒子。将来接入真实事件后，不能用“当前不画”代替“仍要淘汰数据”。

需要补：无访客、无 host 事件、sensor 未连接、数据已过期、浏览器 WS 正在重连、慢消费丢样、压测停止/失败。数据过期与清理独立于当前显示层。每个状态有真实依据，不拿随机动画填空。

### 3.8 交互和可访问性还只是草图

模式项当前是带 onclick 的 div；小屏只在 900px 隐藏侧栏，仍留固定左栏和六列指标定义。需要在对应 UI 课中增加可键盘操作的按钮、选中状态、紧凑布局和减少运动选项，并通过实际窄屏检查确认可用。

这些是源码暴露的待验证点，不等于已观察到每个设备的显示缺陷。先补真实事件链，再做一次有针对性的界面完善。

## 4. 一次访客体验应该怎样闭环

1. 打开首页，明确 LIVE/DEMO/HISTORY，看到连接状态。
2. 自己的节点出现，知道它代表当前连接，能通过移动和点击产生即时反馈。
3. 没有其他人时提供双窗口体验方法；有其他连接时能看到其活动。
4. 切 Host Radar，sensor 未连接就解释原因；连接后显示最近真实事件及观测范围。
5. 点击一个端口，选中对应事件并读懂它是一次 SYN 还是后续连接状态。
6. System 叠加的是两个明确来源的层，不根据 IP 就把 host source 和站内 Session 合并成同一个人。
7. Benchmark 展示真实记录；视觉演示和管理员负载控制各有清楚标签。

首个让朋友试用的版本，以前四步可解释为目标，不要求完成 Ghost 和 C100K。

## 5. Host Radar 最小实现契约

### 观测范围先说清

AF_PACKET 在主机网络设备层接收报文，创建 packet socket 需要对应网络命名空间中的 CAP_NET_RAW。只接收必要接口/协议并尽早过滤，解析后只输出允许的头字段，不保存原始 payload。[Linux packet(7)](https://man7.org/linux/man-pages/man7/packet.7.html)

云侧安全组是实例的虚拟防火墙。由此推导：在到达本机捕获点之前就被上游丢弃的流量，本机 sensor 无法凭空观测；“任何公网端口访问都看得到”必须改为“捕获点可见范围内的入站活动”。[阿里云安全组说明](https://www.alibabacloud.com/help/en/ecs/user-guide/start-using-security-groups)

测试不要求开放所有端口，只对自己的测试来源和指定端口安排验证。还要标明 NAT、代理、接口和 IPv4/IPv6 范围；首个小版本可以只覆盖指定接口 IPv4 TCP SYN，其余显示未覆盖，不能默默假定全覆盖。

### 公开事件草案

```json
{
  "type": "host_event",
  "schema": 1,
  "mode": "live",
  "eventId": "host-example",
  "sensorId": "sensor-example",
  "sourceId": "source-pseudonym",
  "observedAtMs": 1788566400000,
  "transport": "tcp",
  "destinationPort": 8080,
  "kind": "tcp_syn",
  "count": 1
}
```

这是待实现的字段契约，不是当前 `/ws` 已支持的消息。固定消息类型、schema 与枚举；端口 0..65535、count 正整数、ID 有长度限制、时间用于显示和窗口归属。动画仍用客户端接收时钟，不能直接跨时钟做毫秒插值。

公开 sourceId 使用带密钥、带轮换时间桶的伪名设计；密钥保留在服务端，不以短 ID 宣称不可识别。伪名仍可能在同一桶内关联活动；不提供跨天稳定身份承诺，也不把它与 Session 自动绑定。

初始预算：sensor→Gateway 队列最多 1024 项、单条编码不超过 1 KiB；Gateway 最多公开 100 条 host 更新/秒，超量按一秒窗口与端口聚合；浏览器活动效果最多 256 个，事件列表最多 100 条，所有视图都执行过期清理。这些均是实验起始值，压测后再改。

“抓到 SYN 包数”和“连接尝试数”不是同一口径，重传可能重复；初版字段明示 `tcp_syn` 计数，去重或 flow 推断另设测试。sensor 定期上报存活时间，超时显示离线；无事件不等于离线。

## 6. 学习中保留产品成就感

- L1 完成：远程移动真正平滑，得到第一次肉眼可见的改进。
- L4 完成：你能解释和修改的点击事件跨机器出现，常规实现可由 AI 完成。
- L7 完成：你能解释每个数字来自哪里，而不是只会画面板。
- L10 完成：你向自己的测试端口发起一次受控请求，网页显示对应真实事件。
- L8 继续：你能用相同实验对比优化前后的成本。

学习顺序可以在不破坏依赖的前提下交换 L8/L9/L10；不用先实现所有高级基础设施，才允许看到原始愿景。

## 7. 对 v0.1 文档的修订决策

- 保留全主机活动可视化与性能探索；按当前已完成的 Presence 继续，而不是退回最早的 Sensor-first 排期。
- JSON、原生 JS、Canvas 继续作为可交付阶段实现；二进制、React/TS、WebGPU 和 SharedArrayBuffer 由瓶颈与需求决定，不预设为“正式版必选”。
- “关键状态不丢”改成可实施的失败策略：无法及时交付时断开并重取快照；瞬时点击不许诺可靠重放。若要可靠事件历史，另建确认与重放协议。
- Ghost 延后；先规定数据范围、最长保留时间、字节容量、删除和展示模式，不先保存 24 小时明细。
- 云机器配置、5K/25K/100K 与延迟数字均按挑战和假设记录，基准报告才说明实测能力。
